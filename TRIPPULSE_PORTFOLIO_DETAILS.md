# TripPulse: Adaptive AI Travel Copilot ✈️
**Portfolio & Implementation Details Document**

## 1. Project Overview
**TripPulse** is a production-ready, AI-driven travel planning assistant that moves beyond static itinerary generation. Its core differentiator is the **Disruption Engine**, which allows the application to adapt to real-world changes (weather, budget cuts, traffic, exhaustion) by surgically replanning only affected portions of a trip while preserving the overall structure and recalculating the budget in real time.

---

## 2. Technology Stack & Architecture
The application is built on a modern, decoupled Client-Server architecture designed for scalability, security, and responsive UI/UX.

### Core Stack
*   **Frontend**: React 19, TypeScript, Vite, Tailwind CSS v4.
*   **Backend**: Node.js, Express.js, TypeScript.
*   **AI Engine**: Google Gemini 2.5 Flash via `@google/generative-ai` SDK.
*   **Testing**: Vitest, React Testing Library, jsdom.
*   **Deployment**: Multi-stage Docker, Google Cloud Run, Cloud Build, Artifact Registry.

### Architecture Flow
1.  **Client Application**: Collects user constraints (budget, style, mobility needs) via a responsive, accessible form.
2.  **API Gateway (Express)**: Receives requests, applies strict rate limiting, validates input schemas, and applies XSS sanitization.
3.  **AI Service Layer**: Constructs complex, context-aware prompts. Enforces strict JSON output schemas from Gemini. Applies retry logic and markdown sanitization.
4.  **Client UI Update**: Renders the itinerary. If a "Disruption" is triggered, the cycle repeats but with a highly targeted "surgical replanning" prompt.

## 3. Core Implementation Specifics & Differentiators

### A. Strict AI Output & Resilience Layer
One of the main challenges with Generative AI is output variability. TripPulse implements a robust abstraction layer to guarantee application stability:
*   **Structured JSON Enforcement**: The prompt strictly demands a precise JSON schema (`days` array containing `activities` with time, title, description, cost, location).
*   **JSON Sanitization**: A custom middleware (`sanitizeJsonResponse`) strips markdown fences (e.g., ` ```json `) and padded whitespace that LLMs occasionally return.
*   **Retry Mechanism**: The Gemini service layer implements an automated retry loop (up to 3 attempts) that intercepts parse errors and retries the request with a brief backoff, virtually eliminating AI hallucination crashes.

### B. The Disruption Engine (Surgical Replanning)
Instead of regenerating an entire trip when a disruption occurs (which is slow and destroys user context), the system employs **Surgical Replanning**.
*   **Context-Aware Prompting**: When a disruption (e.g., "Heavy Rain") occurs, the AI is fed the *existing* itinerary, the user's original constraints, and the disruption type.
*   **Diff Generation**: The AI is instructed to return the itinerary with new boolean flags: `"replaced": true`, `"original": "<old activity>"`, and `"replacementReason": "<reason>"`.
*   **Visual Diffs**: The React frontend maps over these flags to display a visual diff to the user, crossing out the original activity and highlighting the new, weather-appropriate alternative.

### C. Live Budget Tracking
*   The application maintains state of the `originalBudget`.
*   Every activity generated by the AI includes an `estimatedCost`.
*   The backend aggregates a `totalEstimatedCost`.
*   A reactive `BudgetPanel` constantly compares the current itinerary cost against the original budget, calculating savings or warning of budget overruns, updating instantly during replanning.

## 4. Production Hardening & Evaluation Criteria

The project was heavily optimized across six major evaluation criteria to achieve a top-tier rank:

### I. Security Architecture
*   **Helmet.js Integration**: Implemented comprehensive HTTP security headers including Content Security Policy (CSP) tailored to allow only trusted Google Fonts and Maps APIs, preventing XSS and clickjacking.
*   **Rate Limiting**: Configured `express-rate-limit` (max 20 requests/minute per IP) to prevent API abuse and control LLM token expenditure.
*   **Input Validation & Sanitization**: Custom middleware strictly bounds inputs (e.g., Budget limits, Array sizes) and strips malicious HTML tags before they reach the AI prompt.
*   **Payload Limits**: Express JSON body size restricted to `1mb` to prevent payload-based Denial of Service (DoS).

### II. Code Quality & Maintainability
*   **TypeScript strict mode**: End-to-end typing for API responses, React props, and AI payload schemas.
*   **Error Boundaries**: Implemented a React `ErrorBoundary` component to catch unhandled rendering exceptions, preventing "white screens of death" and offering a graceful recovery UI.
*   **JSDoc Documentation**: Comprehensive comments explaining the purpose, parameters, and return types of critical functions.
*   **Modular Routing**: Clean separation of concerns between Express controllers (`generate`, `replan`) and the Gemini Service abstraction.

### III. Comprehensive Testing (54 Tests)
A robust testing suite using **Vitest** guarantees system stability:
*   **Server Tests (25)**: Deep validation of middleware logic (bounds, edge cases, XSS handling), AI JSON sanitization routines, and constraint builder logic.
*   **Client Tests (29)**: Utilized `@testing-library/react` and `jsdom` to test React components. Includes rendering checks, ARIA role validation, conditional UI display, form validation, and interactive state changes.

### IV. Accessibility (A11y / WCAG 2.1 AA Compliant)
*   **Reduced Motion**: Implemented `@media (prefers-reduced-motion: reduce)` in CSS to automatically disable all animations and smooth scrolling for users with vestibular disorders.
*   **Keyboard Navigation**: Added high-visibility `focus-visible` outlines and a "Skip to main content" hidden link for screen reader and keyboard-only users.
*   **Semantic HTML & ARIA**: Extensive use of `role="banner"`, `role="status"`, `aria-live="polite"` (for AI loading states), and `aria-hidden` for decorative icons.

### V. Performance & Efficiency
*   **Response Compression**: Utilized Express `compression` middleware to Gzip all JSON API responses and static assets.
*   **Static Asset Caching**: Implemented `max-age=1d` and `etag` caching headers for frontend assets served by Node in production.
*   **Multi-stage Docker Builds**: Optimized the Dockerfile to compile TypeScript, build the Vite client, prune devDependencies, and copy only the compiled artifacts into a minimal Node runtime image, drastically reducing image size and cold start times.

### VI. Google Services Ecosystem
*   **Generative Language API**: Leveraged Gemini 2.5 Flash for high-speed, cost-effective structured data generation.
*   **Google Cloud Run**: Deployed as a serverless container, allowing scale-to-zero to save costs while handling concurrent connections securely via IAM policies.
*   **Google Maps Integration**: Dynamically generates targeted `https://www.google.com/maps/search/?api=1&query=...` URLs for every AI-generated activity, seamlessly linking users to real-world navigation.
